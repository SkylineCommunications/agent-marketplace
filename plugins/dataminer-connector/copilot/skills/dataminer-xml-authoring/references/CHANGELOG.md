# dataminer-xml-authoring — Archived Changelog (v2.8–v2.20)

Versions v2.21 and later are in `SKILL.md`.

| Version | Date | Changes |
|---------|------|---------|
| 2.20 | 2026-06-25 | Strengthened Standalone Parameter Naming Convention: extended violations note to explicitly cover multi-word device-identity parameters at PID 1–10 range (`SoftwareVersion` → `softwareVersion`, `FirmwareVersion` → `firmwareVersion`, `IpAddress` → `ipAddress`, `SerialNumber` → `serialNumber`); added `IpAddress`, `SerialNumber`, `DeviceModel`, `ManufacturerName` rows to conversion table; updated Pre-Completion Checklist camelCase item to flag low-PID device-identity params as prime violation sources. |
| 2.19 | 2026-06-24 | Strengthened TABLE GENERATION GATE rule 10: added explicit prohibition on empty `<Discreets />` inside `<Type>table</Type>` measurement — triggers same MAJOR "Missing Discreet tag(s)" finding. Added discrete param alarm threshold guidance in `authoring-best-practices.md` (link-state/status enum examples). Clarified Packets unit for packet/frame counter columns and added 2.11.1 suppression example for cumulative counters. |
| 2.18 | 2026-06-24 | Strengthened standalone parameter camelCase rule: added dedicated "Standalone Parameter Naming Convention" subsection under Parameters with a conversion table (`Hostname` → `hostname`, `SoftwareVersion` → `softwareVersion`, `AdminStatus` → `adminStatus`, etc.). Expanded Pre-Completion Checklist camelCase item with `Hostname` and `SoftwareVersion` as explicit failing examples and a note that single-word device-property names are a prime violation source. |
| 2.17 | 2026-06-19 | Clarified standalone (non-table) parameter naming: `<Name>` MUST use camelCase (e.g., `systemDescription`, `systemName`) — NEVER PascalCase for read/write/dummy/fixed/group params that are not table columns. Updated Parameters and Read/Write pair XML examples to use camelCase names. Added "Standalone Parameter Naming Convention" subsection under Parameters. Added Pre-Completion Checklist item for standalone parameter camelCase. |
| 2.16 | 2026-06-09 | Added TABLE GENERATION GATE rule 12: multiple tables on the same page must be stacked vertically (Row 0, 1, 2 …) — never all at Row 0 Column 0. Column 1 only for narrow tables. Added Pre-Completion Checklist item for multi-table position uniqueness. Added "Multi-Table Page Layout" subsection to `authoring-best-practices.md`. Added one-liner to `dataminer-protocol-xml.instructions.md`. |
| 2.15 | 2026-05-28 | Upgraded XML Formatting section: changed bullets to hard-rule callout box; added explicit note that skeleton uses spaces for markdown readability only — all generated XML output MUST use tab characters. |
| 2.14 | 2026-05-27 | Added pointer in Schema Lookups callout to the Authority Matrix in `dataminer-protocol-validator-prevention/SKILL.md` (single source of truth for the XML triangle ownership). |
| 2.13 | 2026-05-27 | Added dedicated `references/table-relations.md` covering relation path semantics, EPM ordering rules, relation options (`includeInAlarms`, `chain`), FK column conventions, and tree control / EPM / view table integration. Replaced inline relations section in `authoring-best-practices.md` with compact summary + cross-reference. Updated routing table, Conditions & Relations section, and cross-references in `specialized-features.md`. |
| 2.12 | 2026-05-24 | Added "Schema Lookups (Cross-Reference)" callout under Reference Files: this skill's `protocol-*.md` files are pedagogical/authoring-oriented; `dataminer-protocol-xml-reference` is the closed-world schema authority and wins on schema-fact conflicts. |
| 2.11 | 2026-05-11 | Corrected TABLE GENERATION GATE rule 9 and Pre-Completion Checklist volatile item: volatile is NOT required on all dynamic tables — use it ONLY when all of these hold: no alarm monitoring, no save columns, no foreign keys, not DCF, not DVE. REQUIRED for high-churn tables (>7 changes/min or >10 000/day). Also corrected dataminer-protocol-xml.instructions.md to match. Source: DataMiner docs Persisting Tables — Volatile Tables section. |
| 2.10 | 2026-04-21 | Reference consolidation: moved 6 protocol-* schema files (protocol-core, protocol-params, protocol-communication, protocol-execution, protocol-metadata, protocol-types) from dataminer-xsd-reference into this skill. Merged alarming-monitoring, ui-guidelines, conditions-relations, and measurement-discrete-types into new authoring-best-practices.md. Removed common-mistakes.md and parameter-write-pairs.md (content covered by dataminer-protocol-rules.md). Removed xsd-allowed-values.md reference row and MANDATORY note (covered by protocol-types.md). Added TABLE GENERATION GATE rule 2b: display key column `<Interprete><Type>` MUST be `string` (not double) — distinct MAJOR from PK rule. Added TABLE GENERATION GATE rule 10: table array param `<Measurement>` MUST use `table` type — NEVER `discreet` (triggers "Missing 'Measurement/Discreets' tag for 'discreet' Param" in bulk). Added display key column string type row to Table Column Pre-Completion Checklist. |
| 2.9 | 2026-04-19 | Added TABLE GENERATION GATE rule 9: volatile required on every dynamically-populated table (NEVER omit or use empty options). Added Alarm/Monitored check to Pre-Completion Checklist with count-based verification. Strengthened Alarming section summary to include mandatory `<Monitored>true</Monitored>` as first child of every `<Alarm>` block. Strengthened Ping Group section: added explicit guidance to assign id=1 to the scalar poll group so ascending-ID ordering keeps it physically first. |
| 2.8 | 2026-04-17 | Added TABLE GENERATION GATE rule 7: table array param Display must have both RTDisplay and Positions (RTDisplay alone cascades to 30+ MINOR findings). Strengthened Pre-Completion Checklist: NamingFormat item now says NEVER displayColumn; column naming item now explicitly warns 'Table in column name = wrong table Name'. |
